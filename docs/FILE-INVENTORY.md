## 01_installation_dashboard/

Web-based orchestration tool for bootstrapping the entire demo environment. Manages multiple OpenShift clusters, installs operators, deploys Tekton pipelines, configures Portworx storage, builds VMs, deploys the load balancer, onboards to ACM, and manages DR pairs -- all from a single dashboard.

| File | Purpose |
|------|---------|
| `setup.sh` | One-shot bootstrap script -- creates the namespace, RBAC, secrets, PVC, BuildConfig, Service, Route, Deployment, triggers the S2I build, and waits for rollout |

### app/ -- Dashboard Application

The Express server and its browser UI. Runs as a two-container pod (Node.js app + OAuth proxy sidecar).

| File | Purpose |
|------|---------|
| `config.yaml` | Central configuration -- role definitions, operator metadata (namespaces, CSV prefixes, resource costs, CRD groups, webhook prefixes), S3 template, Portworx platform detection rules, and per-platform StorageCluster specs/credential modes |
| `Containerfile` | Container build -- UBI9 Node.js 22 minimal, installs deps, copies app, exposes 8080 |
| `package.json` | App dependencies: Express for HTTP routing, js-yaml for YAML parsing |
| `package-lock.json` | Locked dependency tree for reproducible installs |
| `README.md` | Bootstrap guide, installation order, phase descriptions (Infrastructure, Workload, Demo) |
| `server.js` | Express server -- orchestrates the full API surface: cluster CRUD, operator install/uninstall/scan, role assignment with capacity checks, Tekton pipeline management, StorageCluster deployment, S3/license config, DR pair and protection group lifecycle, orphan audit, deep clean, and SSE event streaming to all connected browsers |

#### app/lib/ -- Server Modules

| File | Purpose |
|------|---------|
| `cluster.js` | Cluster state management -- stores cluster data in a K8s Secret (or local JSON), handles OAuth token negotiation against each OpenShift API, provides `apiRequest()` for authenticated calls to remote clusters, manages LB position ordering, Portworx credentials, and dashboard config persistence |
| `config.js` | Loads and caches `config.yaml` -- single `get()` accessor used by every other module |
| `operators.js` | Operator lifecycle engine -- platform-aware prerequisite checks (worker nodes, instance types, STS detection, ARO service principal validation), CSV status polling, multi-document YAML apply via server-side apply, dynamic channel resolution from PackageManifests, CRD readiness waits, console plugin enablement, and full uninstall (CR, Subscription, CSV, webhooks, CRDs, namespace) |
| `pipelines.js` | Tekton pipeline manager -- loads pipeline/task/trigger YAML from the `tekton/` directory, injects namespaces, applies via server-side apply, grants privileged SCC and MTV provider RBAC, waits for Tekton CRDs, and checks deployment status by probing key resources |
| `roles.js` | Role engine -- loads role definitions from config, maps roles to operators, calculates per-cluster resource capacity from node data, and gates role assignment on available CPU/memory |
| `storagecluster.js` | Portworx StorageCluster manager -- resolves platform from infrastructure API (Azure/AWS/AWS-STS/GCP), reads the matching spec template, injects credentials (secret or workload identity), applies node placement rules (infra taint exclusion), creates cloud credential secrets, and deploys/updates/deletes StorageClusters via the K8s API |
| `templates.js` | YAML template engine -- reads operator manifest directories, resolves `{{mustache}}` placeholders against config and VMware cluster data, generates per-cluster YAML snapshots, and provides read/write/delete for the per-cluster YAML store; also loads DR templates (DRP, PG) with variable injection |

#### app/public/ -- Browser UI

| File | Purpose |
|------|---------|
| `app.js` | Single-page application JavaScript -- cluster sidebar, role assignment cards, operator scan results, pipeline run viewer, StorageCluster status, demo DR controls, SSE event handling, drag-and-drop cluster reordering, and log panel |
| `index.html` | Dashboard HTML shell -- sidebar navigation (Overview, Demo Order, Clusters, Configuration), main content area with tabbed cluster detail views (Roles, Setup, Pipelines, Portworx, YAML) |
| `styles.css` | Dark-theme CSS -- layout, cards, status badges, animations, responsive sidebar |

### pipelines/ -- Tekton CI/CD System

Build system that produces VM images, deploys the artifact server and load balancer, onboards ACM clusters, and activates Portworx licenses -- all inside OpenShift using Tekton.

| File | Purpose |
|------|---------|
| `README.md` | Build system overview -- prerequisites, bootstrap steps, pipeline run instructions |
| `setup.sh` | Bootstrap script -- installs the Pipelines operator if missing, creates the namespace, grants privileged SCC, applies all Tekton resources |
| `teardown.sh` | Deletes the entire build namespace (with confirmation prompt), leaving the Pipelines operator installed |

#### pipelines/builder/

| File | Purpose |
|------|---------|
| `buildconfig.yml` | BuildConfig + ImageStream for the `golden-builder` container image (binary build from Containerfile) |
| `Containerfile` | Fedora 44 base with guestfs-tools and qemu-img -- the build environment for creating golden VM disk images offline |

#### pipelines/scripts/

Shell scripts that run inside Tekton task pods during pipeline execution.

| File | Purpose |
|------|---------|
| `01_check_db_seed.sh` | Validation script -- checks PostgreSQL service, TCP listener, role/database/table existence, pg_hba config, listen_addresses, and end-to-end TCP connectivity as the app user |
| `02_wandering_db_seed.sh` | Database seed script -- starts PostgreSQL if needed, creates the `todo` role and database, creates the `stops` table with the correct schema, and verifies TCP connectivity |
| `03_restart_frontend.sh` | Frontend restart script -- stops the wandering-workload service, re-resolves the DB host (Avahi on VMware, direct on KVM), and restarts the service |
| `build-golden-vm.sh` | Golden VM builder -- creates a base Alpine VM from scratch using guestfs-tools (downloads Alpine ISO, installs to disk, configures UEFI/OpenRC/networking/SSH/qemu-guest-agent, bakes in the app source and build scripts, converts to VMDK) |
| `build-vm.sh` | Purpose-built VM builder -- takes the golden VM and customizes it into either a `frontend` (Node.js + Avahi) or `backend` (PostgreSQL + Avahi) variant, then converts to VMDK |
| `platform_network.sh` | Boot-time platform detection service -- detects KVM vs VMware via `virt-what` and writes DHCP (KubeVirt masquerade) or preserves static (VMware) network config in `/etc/network/interfaces` |
| `vmware_network.sh` | VMware network switch script -- waits for a DHCP lease, derives the subnet, then switches to a static IP ending in `.202` on the same network; runs connectivity tests afterward |

## 02_workload/

The Wandering Workload application -- a two-tier Node.js + PostgreSQL map app that runs natively on VMs. Each "stop" plants a pin on a topographic map, capturing the infrastructure route URL that served the request.

| File | Purpose |
|------|---------|
| `.env.example` | Template for environment variables -- DB_HOST, DB_PORT, DB_USER, DB_PASSWORD, DB_NAME, PORT (documents the `wandering-backend-svc` hostname resolution mechanism) |
| `package.json` | App dependencies: Express for HTTP, pg for PostgreSQL client |
| `package-lock.json` | Locked dependency tree |
| `server.js` | Express server -- connects to PostgreSQL via `DB_HOST`, serves the map UI, provides REST API for stops CRUD (`/api/stops`), captures route URL from request headers, assigns cycling pin colors from an 8-color palette, exposes `/health` endpoint |
| `public/app.js` | Map UI JavaScript -- renders topographic terrain with SVG contour lines, places numbered pins with drop animation, draws dashed trail between stops, animates a pulsing VM marker at the current position, renders sidebar with stop list and route labels |
| `public/index.html` | Map app HTML shell -- loads Space Grotesk and IBM Plex Mono fonts, sets up the terrain canvas and sidebar layout |
| `public/standalone.html` | Self-contained design prototype -- mirrors the production UI with an in-memory mock backend (same data shape as `/api/stops`), used for iterating on the design without a running server |
| `public/styles.css` | Map app CSS -- terrain styling, pin animations (drop-in, pulse), sidebar layout, scrollbar theming |

## 04_loadbalancer_app/

Visual reverse proxy and switchable load balancer for the demo. Gives the audience one stable URL that follows the workload wherever it goes, with a dashboard showing every backend as a clickable node with live health status.

| File | Purpose |
|------|---------|
| `config.yaml` | Local development config -- two nodes on localhost, domain set to `localhost` |
| `configmap.yaml` | Production ConfigMap -- example three-node config (Legacy VM, On-Prem OpenShift, Cloud) with real-world domain and URLs |
| `Containerfile` | Container build -- Red Hat Node.js 22, copies server, dashboard, and config |
| `dashboard.html` | Big-screen dashboard HTML -- full-window animated control panel with clickable backend nodes (VM/cloud/baremetal icons), live health indicators, SSE-driven state updates, and a stable `/go` iframe for the active backend |
| `hosts.sh` | Adds/removes `/etc/hosts` entries for the load balancer's configured domain (reads from `config.yaml`) |
| `package.json` | Zero dependencies -- the server uses only Node.js built-ins |
| `README.md` | Architecture overview, quick start, API reference, deployment options (local, podman, OpenShift) |
| `server.js` | Zero-dependency Node.js server -- control plane (dashboard, REST API, SSE streaming) and data plane (HTTP reverse proxy to active backend) in one process; watches `config.yaml` for live-reload; health checks backends every 5 seconds |
| `trigger.sh` | CLI helper to switch the active backend via `curl POST /api/activate` -- used by demo scripts and Ansible hooks |
