## `apps/wandering-workload/` — The Wandering Workload (map app)

The application being migrated. Two-tier Node.js + PostgreSQL. Runs natively
on VMs, not in containers.

| File | Demo role | Description |
|------|-----------|-------------|
| `server.js` | Core | Express API server. CRUD for stops (pins), `/health` endpoint, infinite DB retry, route capture from request headers |
| `public/index.html` | Core | Map UI: topographic terrain, sidebar, pin placement, VM animation, zoom/pan, route inspector |
| `public/app.js` | Core | Frontend logic: procedural contour rendering, pin management, trail drawing, stats |
| `public/styles.css` | Core | Stylesheet for the map UI |
| `public/standalone.html` | Alternate | Standalone variant of the UI (no sidebar) |
| `package.json` | Setup | Dependencies: `express`, `pg`. Node >=18 |
| `package-lock.json` | Setup | Locked dependency tree |
| `.env.example` | Setup | Example environment variables (`DB_HOST`, `PORT`, etc.) |

## `apps/loadbalancer/` — The Faux Application Load Balancer

Containerized Nginx + Node.js dashboard. Gives the demo a single stable URL
and a visual control plane for switching backends.

| File | Demo role | Description |
|------|-----------|-------------|
| `server.js` | Core | Node.js dashboard server: config parsing, SSE broadcasts, `/api/activate` switches, health checks, `/go` iframe endpoint. Zero runtime dependencies |
| `dashboard.html` | Core | Visual dashboard UI: animated node graphics, dark/light mode, health indicators, click-to-switch |
| `config.yaml` | Config | Local dev node definitions (positions, URLs, icons) |
| `configmap.yaml` | Config | Production ConfigMap with node definitions. Hot-reloads on save |
| `Containerfile` | Build | Container image definition: `node:18-alpine` + nginx + bash |
| `nginx_conf/nginx.conf` | Config | Nginx base config: HTTP→HTTPS redirect, `dashboard.*` virtual host (→ Node.js), default virtual host (→ active backend via `active_backend.conf`) |
| `switch_backend.sh` | Core | Called by dashboard on every switch. Writes `active_backend.conf` with new `proxy_pass` + `Host` header, then `nginx -s reload` |
| `hosts.sh` | Setup | Add/remove `/etc/hosts` entries for the vanity domain. Reads the domain from `config.yaml` |
| `trigger.sh` | Integration | CLI trigger for switching backends. Wraps `curl POST /api/activate`. Usable from Ansible, hooks, or by hand |
| `deployment.yaml` | Deploy | Generated pod spec (hostPort 80/443/8080). Gitignored — regenerated by `deploy_podman.yml` |
| `package.json` | Metadata | Node metadata. Zero runtime dependencies |
| *(Ansible playbooks moved to `ansible/loadbalancer/`)* | Deploy | See `ansible/loadbalancer/deploy_podman.yml` and `teardown_podman.yml` |
| `test/harness.js` | Test | API smoke test for the dashboard server |
| `test/dummy-targets.js` | Test | Starts dummy HTTP backends on port 9090 for local testing |
| `test/config.test.yaml` | Test | Test configuration with dummy node URLs |

## `ansible/golden-images/` — Golden VM Image Builders

Build golden VM images offline on a Linux KVM/libvirt host. The demo uses the
shrunk Fedora image so MTV has less data to copy.

| File | Demo role | Description |
|------|-----------|-------------|
| `fedora-small.yml` | **Primary** | Shrunk golden image (~1.7 GB). Downloads Fedora 44 Cloud Base, customises (packages, repo, users), seals, pre-shrinks BTRFS with `guestfish`, `virt-resize` into smaller disk, converts to VMDK |
| `fedora.yml` | Alternate | Full-size golden (5 GB). Same guest config, no shrink step |
| `fedora-ext4.yml` | Alternate | Converts BTRFS root to EXT4 for simpler shrinking |
| `fedora-min.yml` | Alternate | Kickstart-based minimal Fedora (~1 GB). EXT4. Different guest, needs MTV re-test |
| `fedora-small-virtbuilder.yml` | Alternate | Builds at target size from scratch via `virt-builder`. Different partition layout |
| `alpine/golden.yml` | Experimental | Alpine 3.21 golden (~640M). OpenRC instead of systemd. Env-detect needs porting |
| `alpine/README.md` | Reference | Alpine build docs, OpenRC cheat sheet, MTV raw-copy TODOs |
| `alpine/services.yml` | Experimental | Alpine service definitions |

## `ansible/vm-configure/` — VM Configuration Playbooks

Run locally on each VM (`connection: local`) to turn a golden image clone into
a frontend or backend. No control node, no SSH.

| File | Demo role | Description |
|------|-----------|-------------|
| `backend.yml` | Core | Pins static IP (default `198.51.100.41`), installs `wandering-env-detect`, initialises PostgreSQL, creates `todo` role/db and `stops` table, allows remote connections (pg_hba + scram-sha-256), disables firewalld, enables Postgres at boot |
| `frontend.yml` | Core | Pins static IP (default `198.51.100.202`), installs `wandering-env-detect`, installs Node.js, deploys app to `/opt/wandering-workload`, creates `wandering-workload` systemd service |
| `combined.yml` | Fallback | Both tiers on one VM with `DB_HOST=127.0.0.1`. No env-detect choreography needed |
| `backend-undo.yml` | Teardown | Removes PostgreSQL config and **wipes all data** (`/var/lib/pgsql/data`) |
| `frontend-undo.yml` | Teardown | Removes app, systemd service, env file, env-detect |
| `combined-undo.yml` | Teardown | Both teardowns on one VM |
| `alpine/frontend.yml` | Experimental | Alpine frontend config (OpenRC) |
| `alpine/backend.yml` | Experimental | Alpine backend config (OpenRC) |
| `alpine/combined.yml` | Experimental | Alpine combined config |
| `alpine/backend-undo.yml` | Experimental | Alpine backend teardown |
| `alpine/combined-undo.yml` | Experimental | Alpine combined teardown |
| `alpine/frontend-undo.yml` | Experimental | Alpine frontend teardown |

## `scripts/` — Demo Automation

Shell scripts for every phase of the demo. All source `_lib.sh` for credential
loading and cluster login.

For the full script reference (what each script does, what cluster to run it on,
and the credential management workflow), see [demo-scripts.md](demo-scripts.md).

```
scripts/
├── _lib.sh                           # shared credential loading + oc login helpers
├── cluster-setup/
│   ├── 01-install-portworx.sh        # install/upgrade Portworx on all spokes
│   ├── 02-configure-spoke-rbac.sh    # RBAC + housekeeping on all spokes
│   ├── 03-set-stork-admin-namespace.sh  # stork admin-namespace (required)
│   ├── 04-prep-migration-2tier.sh    # pre-seed MTV target (2-tier)
│   └── 05-prep-migration-aio.sh      # pre-seed MTV target (all-in-one)
├── migration/
│   ├── 01-switch-cluster.sh          # switch oc context
│   └── 02-refresh-mtv-inventory.sh   # force vCenter re-scan
├── dr/
│   ├── 02-create-dr-pairs.sh         # create DR pairs on hub
│   └── 03-create-protection-group.sh # create ProtectionGroup for one hop
└── cleanup/
    ├── 01-teardown-mtv-workload.sh   # delete VMs/PVCs from a cluster
    ├── 02-delete-dr-pairs.sh         # remove DR pairs from hub
    ├── 03-deep-clean-drp.sh          # deep clean all DR state
    └── 04-audit-orphans.sh           # audit for orphaned resources
```
